HDR reference assets generated by `tools/generate_hdr_reference.py` live here.

The intended default artifact is `hdr_reference.avif`, which gives users a known-good gain-map sample to verify that:
- their browser is showing the HDR version on an HDR-capable display
- Windows HDR is actually enabled for their monitor
- the app's AVIF gain-map export path is producing a viewable file

If an HDR AVIF looks different between Windows Photos and a browser, treat that as a color-management or matrix-signaling bug first, not as proof that the monitor is wrong.

Current local finding as of April 8, 2026:
- Brave is the preferred validation target for AVIF gain-map HDR.
- Windows Photos may display the same AVIF gain-map file without switching into HDR mode even when the file behaves correctly in Brave.
- When `ultrahdr_app` is available, `tools/generate_ultrahdr_reference.py` creates a JPEG Ultra HDR sample and validates legacy SDR decoding, embedded Ultra HDR v1 / ISO 21496-1 metadata, libultrahdr HDR decoding, and brighter reconstructed highlights.
