Library picture flow

How a photo gets from disk to the screen in the Library, which part of the app does each piece of work, what is kept, and how long each piece takes today. As of October 26, 2026 (after commits a8540f8 stored screen previews and 64482d8 startup). Timings come from Steve's own app runs (backend.log, Oct 25–26) unless marked otherwise. Grade timings are out of scope. Words follow the master PRD glossary.

The four workers

WorkerWhat it isWhat it does in the Library
PageThe app window (Electron). Runs the Library screen and talks to the graphics card through WebGPU.Decides what to show; keeps finished thumbnails and screen previews in memory; sends drawing and RAW development work to the graphics card; shows quick draws and sharp draws.
BackendThe main Python process (the same one Grade uses). The only writer of the database and settings files.Lists folders from the index; checks and reads the scene cache and stored screen previews; reads RAW sensor data (LibRaw) and decodes JPEG/PNG/TIFF; pulls camera previews out of RAWs; saves scene data after a draw.
HelperA second Python process (hdr-library) at below-normal priority, with separate lanes: main, picture, index, check, stored, kept.Folder scans and background indexing of pinned folders; camera details; writing stored screen previews (JPEG XL encode); CPU decoding for HEIC/JPEG XL/AVIF. Pauses whenever Grade, import or export is working.
Graphics cardOne shared card. Library drawing, RAW development, Grade, Proof and export all queue for it.Develops RAWs (highlight reconstruction, demosaic, colour); draws every thumbnail and screen preview with the current grade, Denoise, Film Look and HDR/SDR mode.

Where the time goes now

Ranked by how much you'd feel it, from the Oct 26 15:56–16:02 HDR try. This is the list to make trade-offs from.

  1. 1Developing a never-viewed RAW BUG10–26 s Was about 3 s on Oct 25. Developing ahead lets several RAWs share the graphics card, so the photo you're on waits for the ones ahead. Graphics card
  2. 2Opening a folder during a development BUG16–22 s wait The folder scan itself takes 0.04 s, but the helper stops taking any new work while a photo is being developed ("source busy"), so the scan sits in the queue. Helper
  3. 3Sharp draw for graded photos with Denoise1.4 s typical, up to 3.8 s Denoise preparation, every time the photo isn't already in the ready window or stored. It also holds up quick draws by up to 1.45 s. Graphics card
  4. 4Back to the grid after fullscreen BUG0.4–4.2 s Cells redraw from camera previews (undeveloped look), then the finished thumbnail comes back. Camera previews are pulled out of the RAW again each time; they are not kept. Page Backend
  5. 5HEIC, JPEG XL and AVIF first pictures4–8 s (AVIF gain map up to 12.7 s) These go through a slower CPU route instead of the graphics card. Helper Backend
  6. 6Sharp draw from a stored screen preview0.24 s SDR · 0.28 s HDR Target about 0.1 s. Reading and decoding the file takes 0.06–0.09 s; most of the rest is getting it from the backend into the page. Backend Page
  7. 7Never-prepared JPEG/PNG sharp draw0.85–1.1 s Accepted for now; target under 1 s (Steve, Oct 26). TIFF is 2.0–2.4 s.

6 · Open a photo in Grade

Page
Backend
Helper
Graphics card
1
Grade appears and loads the photo
Grade opens the original at full quality through its own route. Library pictures and stored previews are not used; no thumbnail stand-in is shown. (Grade timing not covered here.)
2
Helper pauses
Whenever Grade, import or export is working, the helper's background lanes wait. Already-kept pictures are still served.
3
Saving a grade makes that photo's finished pictures stale
The grade identity changes, so its pool thumbnail, ready-window entry and stored screen previews no longer match. Scene data is ungraded, so it stays valid unless the change affects development itself (for example RAW settings); then the next Library visit only re-grades and re-draws (stage 3 B / stage 4 D) and stores a new screen preview.
Settings file (.hdrf)

Everything that is kept

Finished pictures include the grade and HDR/SDR mode and are ready to show. Scene data is developed but ungraded: cheaper than a new development, but it still needs grading, Denoise and drawing.
