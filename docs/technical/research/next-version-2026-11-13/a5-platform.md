## 1. JPEG XL colour tags off Windows

**Read in code/docs:** `codebase/backend/hdr_finisher/jpegxl.py:490-507` already falls back on missing helper, failed process, invalid JSON or wrong schema. The Python prefix reader supplies dimensions/precision, not colour (`:532-569`). `:687` onwards accepts only supported structured DATA profiles; ORIGINAL is not necessarily the interpretation of returned pixels. The native helper requests BASIC_INFO and COLOR_ENCODING without a pixel output buffer (`codebase/tools/jpegxl-info/info.cpp:28-54`). ICC-only profiles return null (`BUILD.txt:1-6`). This distinction must survive any replacement. `jpegxl.py:115` exposes the manual interpretation gate.

**Read in upstream sources, accessed November 13, 2026:** [libjxl 0.12.0 ImageMetadata grammar](https://github.com/libjxl/libjxl/blob/v0.12.0/lib/jxl/image_metadata.cc) and [ColorEncoding grammar](https://github.com/libjxl/libjxl/blob/v0.12.0/lib/jxl/color_encoding_internal.h). The colour subset has an all-default shortcut, ICC desire, colour-space enum, conditional white point/custom coordinates, conditional primaries/custom coordinates, enum transfer or gamma, and rendering intent. Reaching it also requires integer-sample flags, variable extra-channel descriptions and metadata conditionals. ICC bytes use additional coding; detecting ICC and retaining manual selection is much smaller than implementing ICC decoding. **Estimated:** roughly 300–600 additional Python lines with bounded container reassembly and validation, plus fixtures/tests; this is not a measured implementation size. DATA versus ORIGINAL semantics, including XYB/default decoder output, make simply reading original colour enums unsafe.

**Read in package metadata, accessed November 13, 2026:** [imagecodecs 2026.6.26 files](https://pypi.org/pypi/imagecodecs/2026.6.26/json) include `cp312-abi3-macosx_11_0_arm64` and `cp312-abi3-manylinux_2_28_x86_64`; [imagecodecs licence](https://pypi.org/project/imagecodecs/) is BSD-3-Clause. [pillow-jxl-plugin 1.3.8 files](https://pypi.org/pypi/pillow-jxl-plugin/1.3.8/json) include `cp312-cp312-macosx_11_0_arm64` and `manylinux_2_17_x86_64`; its [source licence](https://github.com/Isotr0py/pillow-jpegxl-plugin/blob/main/LICENSE) is GPLv3. These are availability checks, not wheel execution tests. Preserve notices for bundled libjxl and dependencies independently of the wrapper licence.

**Recommendation:** keep imagecodecs for pixels and build the existing metadata helper from pinned, hash-verified sources in release CI. Prefer static dependencies for the tiny helper to avoid dylib/rpath and ELF loader mistakes; verify the actual resulting dependency list rather than assume static linking worked. Disable unused tools/tests/JPEG reconstruction features where supported. libjxl needs its pinned submodules/dependencies (not just headers); reuse upstream CMake configuration, including Highway/Brotli and colour-management dependencies as selected by that build. Mac dynamic deployment, if used, needs relative install names and libraries inside the backend bundle before its final signing step. Linux must retain the package’s glibc baseline. Flatpak must declare hash-pinned offline sources and build inside its SDK, placing helper/dependencies under /app; do not depend on host PATH or network pip at runtime. `packaging/flatpak/io.github.LucienMidnight.hdr-finisher.yml` is a separate build path, not automatically fixed by the desktop job.

Retain the current fallback even when CI promises a helper. Add a subprocess timeout and bounded diagnostics; a broken optional metadata reader must not repeat the 0.9.2 non-Windows open failure. Unsupported ICC/custom colour stays visibly manual, never silently called sRGB. Full ICC colour management is outside this proposal.

Test plan: commit tiny independently tagged fixtures plus a manifest of expected DATA and ORIGINAL tags, precision and provenance. Cover sRGB, linear sRGB, Display P3, BT.2020/PQ and HLG; integer 8/10/12/16 and float; lossless/XYB cases where ORIGINAL and DATA differ; raw codestream, jxlc and split jxlp containers; ICC-only/custom white point/primaries/gamma; truncation and malformed boxes. Compare known expected values, not only two implementations sharing a bug. On Windows, macOS and Linux runners run Python tests with the helper present and deliberately absent, failing, timed out and returning malformed output. Assert that a valid supported JXL still decodes and exposes manual selection when metadata is unavailable. Package smoke must invoke the packaged helper in an isolated environment with system tools removed from PATH; Flatpak needs its own in-sandbox fixture probe. No new GPU test is needed for the reader itself; verify downstream interpretation with existing pixel conversion tests.

Decision for Steve: approve the helper approach with ICC/custom profiles remaining manual. **Confidence:** high on architecture and fallback; medium on effort until native dependency closure is checked in packages.
