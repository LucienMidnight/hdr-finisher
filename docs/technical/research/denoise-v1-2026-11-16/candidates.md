# Denoise v1 candidate survey — November 16, 2026

Prototype RawNIND linear, RawNIND Bayer, darktable profiled wavelets, and GALOSH.\
These compare learned restoration with two credible classical approaches; none is approved to ship.\
RawNIND has explicit redistributable weights; several newer papers fail that licensing test.\
The Bayer model looks more practical on the minimum Mac, but changes demosaicing as well as denoising.\
Quality, complete preparation time, HDR safety and whole-app memory must decide the winner.

This is Phase 1 of the [quality trial](../../briefs/denoise-v1-quality-trial-2026-11-16.md), building on [B1](../next-version-2026-11-13/b1-ai-denoise.md) and the [technology watch](../../denoising-technology-watch-2026.md). Research only: no app changes, training, real-photo trial, GPU or Electron run. Sources checked November 16. **M = measured here; R = read from a source; E = estimated; U = unqualified/unknown**, never zero. MB/GB are decimal. Timing estimates are inference/filter work, **not action-to-picture waits**; decode, calibration, demosaic, color conversion, geometry, upload and presentation remain to be measured. No timing acceptance or existing tolerance is changed.

## Recommended four prototypes and adapter contracts

Run the current `adaptive-atrous-v1` defaults, tuned current settings, and Off alongside each. Do not treat a successful load or published PSNR as a quality pass. **Prioritise Bayer RawNIND and profiled wavelets for sensor cleanup**, while linear RawNIND tests the simpler universal-source route and GALOSH tests a small, non-neural alternative.

1. **RawNIND linear: the lowest integration-risk neural comparator.** Harness input is float32 contiguous NCHW `[1,3,512,512]`, scene-linear Rec.2020, no gamma. Convert ACEScg/D60 through the app's existing color transforms, including chromatic adaptation; invert afterward. No ISO/noise parameter is accepted. Use mirror-gathered tiles, trim 64 px each edge, stitch native resolution, then apply **one frame-global scalar** `mean(input)/mean(raw_output)`, as upstream does. Accumulate means over retained cores; never independently gain-match tiles. Near-zero/nonfinite gain is a failed attempt, not permission to invent a gain. Test the upstream normalization first on supported-domain crops. Then separately test finite negatives and >1 values, ±6-stop rescaling, saturated colors and near-black scenes. **Do not clip ACEScg into [0,1] or per-tile min/max-normalize to make it load.** Passing the HDR contract is still unproven. Whole-image affine/gain adapters are experiments, not established exposure invariance.

2. **RawNIND Bayer: the most relevant learned sensor-domain trial.** Obtain visible raw mosaic, CFA pattern/orientation, per-raw-channel black/white levels and camera metadata before AHD/WB. Normalize `(sample-black)/(white-black)` **once**; pack canonical spatial RGGB into `[R,G1,G2,B]` (the green positions matter), float32 `[1,4,512,512]`. Mirror/crop padding must preserve CFA phase, including image edges. The graph returns `[1,3,1024,1024]` camera RGB, not four denoised raw planes; trim **128 output px per edge** and keep 768. Apply upstream frame-global gain matching against packed input before color conversion. Reproduce the upstream reference camera conversion first; then qualify a host adapter using HDR Finisher's established camera matrix, white-balance and calibration conventions **exactly once**, rather than inserting a second WB or copying the demo's matrix inverse without checking its meaning. No sigma/ISO input. The demo clips normalized raw to [0,1]; record that reference behavior, but do not silently introduce new clipping into the app's HDR source path. Unsupported ranges/CFA go to the existing path. This model **replaces demosaic**, so do not pass its RGB output through AHD. Current upstream documents **CoreML CPUOnly** for this variant; keep FP32 CPU as the first prototype. The downloaded June release config predates the `cpu_only` flag: enforce the restriction in the harness/host rather than assuming this archive enforces it.

3. **darktable profiled wavelets: the mature classical calibration comparison.** Feed **float32 camera-linear RGB after AHD, before camera→ACEScg**. Port the current VST, white-balance adaptation, edge-aware decomposition, shrinkage and inverse/bias correction from `denoiseprofile.c` and its referenced helpers; do not port GTK, OpenCL dispatch scaffolding or compatibility migrations. Noise is `Var(x_c)=a_c*x_c+b_c` in normalized sensor units; map precisely to upstream's parameter convention: its older preconditioner squares its stored `b/a`, so do not confuse read-noise standard deviation with variance. If `x'=g*x`, shot coefficient becomes `g*a` and read variance `g²*b`. Fit per-camera/ISO sensor profiles or the harness's synthetic truth, propagate WB gains and account for AHD correlations. ISO alone is not a noise level. No matching profile: use the current measured-noise path, not an unrelated camera's coefficients. Copy/calibrate profile data only with its own licence. Geometry follows denoise for this source-development experiment. Use explicit halo from active scales and the original mirror semantics. For non-RAW RGB, evaluate a **separate fitted-noise adapter** in working RGB; raw-profile coefficients cannot simply be moved through a 3×3 color matrix and treated as independent.

4. **GALOSH RAW: the small-runtime modern classical comparator.** Start with canonical **FP32** raw reference, not faster INT16/WHT4 variants. Feed even-sized, correctly oriented RGGB float32 mosaic with black/white normalization; retain the original sensor coordinate system. CLI contract is `input.bin output.bin W H galosh strength luma chroma alpha sigma_sq`; `alpha` is shot gain and `sigma_sq` is read variance, not read standard deviation [GA-C]. Positive external `alpha` with nonnegative read variance overrides blind fitting. Use harness-calibrated values first, then its blind estimator; one photo-global fit must serve every tile. It produces a corrected mosaic: run **the same AHD, WB and camera→ACEScg development** on input and output. The multiscale chroma support requires a derived halo plus shifted-grid tests; the proposed 128 px starting halo is not a proven bound. The current CLI assumes one global P–G pair: test whether per-CFA noise differences need an adapter, do not promise existing per-channel profiling. Keep the sRGB frontend as a separate SDR reference only: it inverse-gammas and clamps its result and does not satisfy unrestricted linear HDR. The local C build needs OpenMP headers/runtime or an upstream-supported serial build before this Mac can run it; no environment changes were made to solve that here.

### Pipeline and the existing controls

The [v2 contract](../../denoising.md), especially sections 1–4, remains the interactive contract. Actual controls are in `denoise_adaptive.py:AdaptiveControls`: neutral 0.5, Amount 0.5 removes the measured amount, four size multipliers, and existing finest-band Detail Recovery behavior. The old watch's proposed “coherent recovery” is not proof the current implementation already does it.

**E proposed common adapter:** prepare a corrected source once; compute the original-minus-corrected residual in a common developed **scene-linear ACEScg** frame, split into opponent luminance/chroma and the current four size groups, and cache/recombine only the admitted bounded evidence. Amount scales removal, Luminance/Color Noise weight their components, four sizes weight residual bands, Detail Recovery restores only the existing permitted fine/coherent contribution, and Show noise shows **original minus the actual resolved picture**, including after masks. Off and Amount zero use the untouched original; alpha never enters a denoiser. Changing a noise profile/model is explicit Recalculate, not another inference per slider move. A single residual does not reproduce every possible model sigma setting; residual mixing also brings noise back, and cannot prove that lost or invented structure is safe. This is a prototype of control behavior, not an approved semantic replacement or additional cache budget.

For Bayer joint demosaic, **ordinary AHD output and neural camera-RGB output must both be developed through the same downstream color/geometry path** before residual comparison. Removed content includes demosaic differences as well as noise. A clean-input model pass and matched-AHD references must distinguish those in the harness; Show noise cannot be claimed to display pure sensor noise. GALOSH/raw-wavelet methods keep AHD, avoiding that confound. Sensor fixed-pattern/banding and hot pixels are not guaranteed to disappear under any single-image denoiser: compare dark-frame/row-column calibration separately, with detail safeguards, rather than claiming a generic blind network solves them.

For future app integration, raw work must be shared by `backend/hdr_finisher/raw_import.py` (CPU AHD) and `frontend/library-gpu-raw.js` (WGSL normalization, opposed-color repair, AHD and color tail). Today GPU normalization already applies WB before later passes, whereas RawNIND Bayer requires **pre-WB** input. Insert before that amplification or reverse it exactly with calibrated variance; do not feed the post-WB buffer unchanged. Preserve clipped-site masks and current highlight-repair behavior; decide their order by the harness, not by moving a pinned output stage. A raw→raw method continues through existing development; a joint demosaic model must bypass AHD only, not the required color/calibration tail. X-Trans remains CPU-developed and can try the linear model. Developed HDR/renders have no mosaic: current v2 remains their fallback unless the linear candidate passes the full range contract.

**Memory model (E):** RGB float32 is 12 bytes/pixel: 288/732 MB at 24/61 MP; two frames 576/1464 MB. Raw float32 mosaic is 96/244 MB. Add bounded tile workspace/model/session, not an entire padded-image copy; upstream demo's whole-frame `np.pad` must become bounded tile gathering in any implementation. RawNIND estimates use the **measured ~0.58/0.61 GB worker** conservatively plus source/destination; distinguish already owned app input from genuinely additional memory. darktable source reports 5×RGBA CPU buffers and scale-dependent GPU buffers; tiling is mandatory at 61 MP. GALOSH estimate assumes no full-frame pyramid retained. None is an approved reservation or new cache size.

If the non-denoise editor owns `B` GB, admission must count **B + additional model/workspace/output + renderer/native copies and CoreML/GPU allocations**. At B=3.2 GB even ~1.3 GB extra fails the 4.4 GB peak limit. Evict existing eligible caches or refuse/fallback through the established broker; never raise the limit. Library/source/denoise ownership and settled <3.4 GB must be checked together. Release transient sessions/workspaces after preparation if needed. No full-frame 61 MP trial or whole-app memory census occurred here.

**Mac timing derivation (E):** use 6000×4000 and approximately 61 MP 9600×6400. With 384 retained pixels, linear needs 176/425 tiles; Bayer retains 768 sensor pixels and needs 48/117. Multiply the one cold CPU invocation by those counts: 62.95/152.01 s linear, 15.75/38.38 s Bayer. Cold setup is ~0.03 s each. No six-core scaling is assumed; memory bandwidth, thermal state and another worker's activity can dominate. Broad planning ranges are uncertainty estimates, **not performance tolerances**. Linear CPU already looks above the brief's proposed 45 s/24 MP target; Bayer is worth measuring end to end. GPU time on this Mac remains U. GALOSH's published GPU numbers use RTX 4070 Ti/OpenCL and are not a Mac/WGSL promise; darktable costing has no measured Neo anchor. All slow full-size runs belong to Phase 2, serialized with other CPU work.

### Classical licences and patents

- **Current PyPI `bm3d` is still non-commercial.** PyPI JSON reports latest **4.0.3**; downloaded source archive's **`bm3d-4.0.3/LICENSE`** permits only “informational and having non-commercial scope” and forbids network redistribution without consent. It depends on separately restricted `bm4d`. [PyPI/source download][BM-NC] and [TAU software terms][BM-TAU]. **Exclude those packages from a GPL app that may be sold.** GPL app licensing does not cancel these restrictions.
- **BM3D the method is not identical to the restricted package.** [IPOL's downloadable implementation][BM-G] README says **GPL v3+**, supports Unix/Linux/Mac and links FFTW/libpng. Its float-array core can be ported; the PNG demo must not quantize our linear input. GAT before BM3D and bias-corrected inverse afterward are sensible for Poisson–Gaussian RAW; cross-color raw matching is a separate adaptation. **Do not assume GPL IPOL licenses TAU's newer BM3D-CFA code.**
- **Patent check result: unresolved, not “patent-free.”** The searched TAU/IPOL pages did not establish a blanket licence or expiry for all BM3D-related claims. Search also finds patents describing **extensions**, e.g. [US9230161B2](https://patents.google.com/patent/US9230161B2/en), multiple-layer block matching. A patent citing BM3D does not prove basic BM3D infringes it; a 2007 paper does not prove every relevant claim expires in 2027. No identified blocking base-method claim is asserted here, and no freedom-to-operate clearance is claimed. The GPL implementation is usable research material; resolve this bounded question if BM3D becomes a shipping selection.
- **GALOSH discloses US provisional application 64/058,343, May 6, 2026** [GA]. Its actual Apache-2.0 **§3** gives the contributor patent grant for the contribution, including use/sale; NOTICE adds only a voluntary contact request. This supports the licensed prototype, **not a separate unbounded patent clearance claim**. Preserve LICENSE/NOTICE and pin source; do not copy some differently licensed binary. No comparable patent notice was found in the inspected darktable/RawTherapee denoise source headers; that is not proof of absence.
- Classical alternatives worth keeping small: raw variance-stabilised **wavelets** (darktable [rawdenoise.c][DT-R], RawTherapee CFA wavelet/Fourier [RT-C]); NLM with a global fit; calibrated fixed-pattern subtraction before any denoiser. Do not import the TAU inverse-Anscombe sample package assuming it shares a paper's rights: derive documented formulas or use the licensed implementations already surveyed. Bias correction matters in lifted shadows. Statistical Monte Carlo methods needing AOVs/sample variance, OIDN render weights, video/burst methods and diffusion synthesis do not replace single-frame sensor-noise restoration for this trial.
