# Denoise specks and colour blotches — next research round

18 November 2026 · MacBook Neo, A18 Pro, 8 GB · Proposal and CPU diagnostic

**Start with the colour of the spots.** On the Canon night photo, sensor cleanup already takes most of the harsh spots out of the flatter test window. Denoise then makes some remaining peaks stand out against a newly quiet background. Turning up Fine, Medium or Color Noise attacks weak lettering and texture at the same sizes. I recommend a small trial that asks whether a spot’s green or magenta belongs to the wider shadow, and changes only the excess colour. A separate trial should tackle the dark centres that survive this treatment.

## What happened on the Canon

The camera records one colour per sensor site. A low red or blue reading can become a green patch when the missing colours are interpolated. Several modest errors can form a patch without any individual reading looking exceptional. In the earlier eleven flatter gallery windows, 200 of 547 spots coincided with one extreme sensor reading, 114 with several and 233 with none in the tested footprint. That is an association across the gallery. The last 233 are an unresolved mixture, and a spot with a sensor origin can **also** be exaggerated by Denoise. Signed shadows retain useful colour and exposure latitude. The earlier change of demosaicer and the repair to clipped-highlight noise measurement each left the Canon shadow pits visible. [Sensor evidence](early-outlier-taming.md) · [Demosaic trial](lmmse-demosaic.md) · [Noise measurement](dark-noise-strength.md)

Denoise decides how much fine detail to keep by comparing local variation in a 7×7 window with expected noise. A clump can pass that test while a faint eyelash fails it. Earlier Canon measurements found a median keep factor of zero in the first four brightness bands, yet the top 0.1% of the finest-band gains reached 0.718. Detail Recovery at 0.5 has no minimum retention floor. The existing bright-bin fix and fine-band tail correction already run. Ignoring only the centre sample previously made a modest difference because the other interpolated samples still carry its colour. [Band measurements and prior ablations](dark-noise-strength.md)

### A test that changes only where Denoise keeps energy

I used the Canon EOS 60D ISO 3200, both original 512 px sensor windows, their central 288 px pictures and the original +4-stop viewing lift. I read native signed AHD with the Canon’s actual colour matrix, production white balance, the current informative whole-photo CPU noise estimate and shipping Denoise controls. I repeated with the optional 2.5σ sensor clamp off and on. Each setting gets its own whole-photo model. **Within each row**, all three pictures share the same developed input and the two filtered pictures share the same model and wavelet coefficients.

The diagnostic reconstructs today’s result and checks every scored RGB value for exact agreement with the production CPU filter. It then replaces the changing keep factor with a single factor for each size and colour component. Each of those 15 factors preserves exactly the same band energy on the scored window, up to float rounding. Only the distribution of that retained energy changes. This is a way to test the mechanism. It would be a poor filter for a photograph containing both text and sky.

A spot here is the older detector’s 1–25 px island. At its strongest pixel I measured its signed contrast in the same display channel in every picture, relative to the typical grain 6–12 pixels away. A map-sensitive location loses at least 25% of that score when the gain is made spatially constant. The last column also requires a same-sign input peak whose score grew by at least 25% under Denoise. Those cutoffs describe this experiment. Tightening both to 35% gives 4 and 137 in the two clamp-on windows. Requiring initial contrast at least as large as typical surrounding grain gives 3 and 143 at the original cutoffs.

**Verdict.** The survivor mechanism is present. In the flatter window, four of the 17 remaining detections have the predicted before-and-after signature. At the other 13 the gain map matters, but the strict test did not identify a pre-existing peak that it made more conspicuous. Differential suppression of colour bands, displacement of a peak and display clipping are possible explanations. In the detail window, 146/421 have the signature, but genuine fine detail can behave the same way. Neither percentage estimates the proportion of noise in the photograph.

The test selects peaks on today’s output, which favours today’s local maxima. In the opposite direction, only 16/212 peaks chosen on the *input* detail window met the same combined rule with the clamp on. In the flat window the old input counter found just one small island. Dense noise can merge into components too large to count. With the clamp off the equal-energy control there produced 3,712 small islands. Counts across different grain textures give a misleading ranking. Use these same-location results for mechanism and Steve’s visual judgement for quality.

The old gallery also gives us two points chosen *before* this test. At its marked detail-window point with the clamp on, the input was slightly green relative to the surrounding ring (+0.076), today’s result slightly magenta (−0.039), and the equal-energy control green again (+0.074). Its brightness deficit deepened from 0.008 to 0.066 under today’s map and returned to 0.005 in the control. Here Denoise changed the *direction* of the local colour difference and deepened the pit. A test tracking only same-sign green–magenta peaks would miss that reversal. At the marked flatter-window point, brightness was the stronger issue after cleanup (+0.154 against its ring, green excess only +0.017). Colour here is display green minus the average of red and blue, relative to its 6–12 px ring. Both measures use 0–1 display units. Neither site has clean truth.

The five newly supplied RAWs were each tested at their predetermined centre, at normal exposure, with the clamp on. Today’s detector found zero islands there on DSC00512, DSC00786, DSC05622 and PC131157 and one on PA310516. These tiny centre samples cannot establish clean shadows or transfer the Canon rate to another camera. They show why the next round needs a marked shadow **and** a detail crop per photo.

## Where each kind of noise belongs

| What the photographer sees | Best place to detect it | Best place to correct it, and why |
| --- | --- | --- |
| Hot or possibly stuck sample | Original signed Bayer phase, before interpolation | The existing optional hot-pixel repair can replace an isolated extreme with evidence from its phase. A single exposure cannot establish a permanently stuck site. Preserve clipped lights, borders and the original clipping evidence. |
| Isolated high or low reading | Same sensor phase, relative to the photo’s own noise versus brightness | Keep the optional soft sensor clamp. Pull the tail toward the noise envelope before interpolation spreads it. Track 3 tests better protection for points and thin lines. |
| Several mildly wrong samples | Inspect the combined colour footprint in post-demosaic camera RGB and its corresponding sensor phases | Hand the footprint to the opponent-colour bands after conversion. Individually plausible sensor readings give too little information to replace them safely. Keep signed AHD for reconstruction. |
| Green or magenta islands | Compare the colour of the island with a wider region on the same side of an edge, using developed colour | Inside Denoise or immediately after its reconstruction, shrink only the excess green–magenta component and preserve scene luminance. Observe the camera RGB stage for attribution before deciding which placement works. |
| Dark centre with coloured or bright rim | Inspect signed brightness and colour separately across wavelet sizes, before and after shrinkage | Adjust the fine-band keep decision in Denoise. A colour pass can fade the rim and still leave the pit. A blanket brightness median also erases print dots and eyelashes. |
| Coarse colour mottle | Low-frequency opponent bands against a broad same-surface colour trend | Correct the uncertain coarse colour bands in Denoise. Use a larger reference for this than for pinpoints. Genuine gradients, stage lighting and coloured shadows must retain their sweep. |
| Fine, even brightness grain | Finest brightness band, measured separately from colour and coarse structure | Retain a controlled share during Denoise reconstruction. A final display check measures evenness and visibility at normal zoom. Film grain stays an artistic finishing control. |
| Spots made conspicuous by Denoise | Compare the same location at input, after normal shrinkage and after a controlled change to the keep factors | Correct the decision inside Denoise. Use after-Denoise analysis to check what escaped. Extra blur at the end would also affect every real edge. |

Pixel cleanup stays Bayer-only. X-Trans, linear DNG and non-RAW can participate in the later developed-image trials. Opposed color keeps its sensor-stage highlight job. Edge colour keeps its developed-highlight job. Review their support boundaries explicitly. Preserve the chosen reconstruction and signed range through the trials. Finishing owns the intended grade, Film Look and highlight ceiling. Deferred Bayer AI would require working highlight reconstruction and explicit re-development from Denoise after v1.

## Four trials, in priority order

The percentages below are **working targets for deciding whether to continue**, relative to the same photo with 2.5σ taming and today’s Denoise. They refer to the appropriate subscore below. They are estimates to challenge, not measured improvements, and cannot be added together. Costs describe proposed work on the 8 GB Neo. GPU seconds and action-to-screen savings are unknown for all four.

**1. Correct colour that is out of place in a shadow.** For 1–25 px spots, estimate the *expected* green–magenta colour from rings roughly 16–48 px away. Split the rings at persistent luminance edges, exclude the candidate footprint, and compare with the photo’s noise at that brightness. Abstain when the reference mixes surfaces or has two plausible hues. For broad mottle, test the same idea one or two wavelet levels coarser. Shrink only the colour excess, preserving ACEScg luminance and the red–blue difference. Compare pre-shrinkage placement against post-Denoise placement with the model frozen. This extends the 9×9 median trial, where 38 colour islands fell to 15 at a severe cost to small real colours. [Earlier colour trial](chroma-cleanup.md)

- **Expected benefit and risk.** Aim for one-third lower conspicuous colour on marked shadows. Expect little change to the dark pits. Protect narrow ridges and optical point profiles across scales. Isolated red/green stars, fine coloured lettering and leaf tips can still lose hue. Eyelashes and cloth may keep their brightness edge while coloured threads lose their identity. Check colour as well as shape.
- **Cost and path to shipping.** CPU prototype with a downsampled regional colour guide and bounded full-resolution correction in tiles. Budget the work by two coarse guide passes and one full-resolution resolve. The previous brute-force wide median alone added 13/36 seconds on 18/42 MP on this Mac. A GPU version would need the same scene-aligned guide and a resolve on the existing Denoise path. First try one experimental on/off method using the existing Color Noise amount. A selected method would need a saved identity and cache invalidation. Stop if safe behaviour requires a per-photo hue blacklist.

**2. Stop isolated wavelet peaks from outliving nearby structure.** Keep the current noise model. In fine bands, reduce a high keep factor when neither a coarser-scale edge/ridge nor a second channel supports a common orientation or optical point profile. Compare this with a simple smoothed keep map as an ablation, then with today’s unchanged map. Limit changes to marked uncertain peaks and allow soft attenuation. Estimate protection upstream of suppression. The present experiment implicates spatial selection, while the earlier centre-exclusion and self-pilot trials already showed the limits of removing one coefficient or filtering everything twice. [Pilot results](pilot-wiener.md)

- **Expected benefit and risk.** Aim for a quarter lower conspicuousness of marked dark pits and rims. The measured 4/17 signature is motivation, not a removable quota. Faint stars can lack a second visible channel. Thin glyphs, eyelashes, fine weave and branching leaves can lack a parent ridge. Preserve ambiguous points and separately check flux, connectivity, orientation and texture on real controls.
- **Cost and path to shipping.** Reuse adjacent wavelet levels, one bounded tile of parent evidence and roughly one extra gate per tested fine band on CPU. GPU preparation would need parent-band evidence before finalising the child and may add a tile pass. Verify seams and slider response first. An experimental Denoise method could share all current sliders and save a method/version only. Stop if the result merely reproduces the loss from turning up Fine.

**3. Replace the sensor spot veto with evidence of actual structure.** On Bayer only, compare today’s 2.5σ clamp, the identical clamp without the neighbour vote, and a third variant with the vote removed and multi-scale ridge/point protection added. Hold floor, signed polarity, area cap and saturation exclusion fixed. Estimate a brightness-conditioned noise envelope over wider same-phase samples outside the suspected footprint. Check aligned structure across CFA phases at their actual offsets. An isolated unresolved point gets conservative treatment. Similar nearby samples never vote to preserve a spot in either new variant.

- **Expected benefit and risk.** A modest incremental gain, worth pursuing only if it yields roughly 10% lower marked sensor-linked salience **and** better real-detail retention than today’s clamp. Simply removing the veto already gave 143 versus 141 islands on the old flat gallery. Undersampled stars, coloured punctuation and catchlights are the hardest risks. Protect elongated lashes, repeating cloth and leaf veins by orientation across scales. An unresolved star and a bad sample can be indistinguishable in one exposure. [Earlier clamp ablation](early-outlier-taming.md)
- **Cost and path to shipping.** Current CPU sensor work adds about 1.2/2.8 seconds at 18/42 MP on the Neo. Try a bounded guide shared across the four phases and apply the extra check only to candidates. The Library GPU RAW route already accepts CPU-tamed DN samples once. Reuse it if qualified, including hot-pixel interaction and both highlight methods. A different sensor method needs explicit opt-in, its own recipe identity and source invalidation on re-development. Keep the existing threshold range for comparison.

**4. Retain a measured amount of even fine grain.** After one of the first two trials removes distracting islands, mix back a bounded share of the photograph’s own finest brightness residual. Reject chroma, coarse maze texture and outlying peaks. Learn the research target from separate clean flat references. At application time use only this photo’s noise estimate, with smooth gain across brightness and tile boundaries. Compare at the same colour cleanup with and without the mix. The earlier single grain preset left 4.1 times the reference brightness grain. [Grain measurements](early-outlier-taming.md)

- **Expected benefit and risk.** Little expected change to the number of physical spots. Seek a 15% reduction in perceived isolation of marked residuals at matched grain amplitude, with no increase in chromatic or coarse tail scores. A star or punctuation can be buried again, eyelashes and weave can acquire false texture, and foliage can recover a maze pattern. Limit the returned component by scale and amplitude. Inspect clean inputs for introduced texture.
- **Cost and path to shipping.** Cheapest if it is one extra multiply/blend in existing CPU/GPU reconstruction. A separate full-resolution cache would change that estimate. Test tile-local reuse first. If the existing Detail Recovery control cannot express it safely, consider one optional “Fine grain” amount saved in the experimental method. Stop if the visual gain comes only from obscuring the photo with more noise.

All four can be written independently in the repository’s GPL-3 code. This proposal ports no external implementation. If a later trial imports code, record its exact source revision, licence and notices. The non-commercial TAU BM3D/BM4D packages are excluded, IPOL’s GPL implementation leaves a patent question open, and GALOSH’s Apache contributor grant has a disclosed provisional application. None is needed here. [Licence survey](candidates.md)

## How to decide if the pictures are better

**Freeze the pictures before testing a candidate.** Keep the 14 earlier gallery windows, both Canon zooms and the original lifts. Today’s main comparison is signed AHD, optional harsh-speck cleanup on at 2.5σ, hot-pixel repair off and Denoise on at its shipping settings. Include a separate clamp-off ablation. For each of the five new RAWs, choose a shadow and a fine-detail area from the *input alone*, record coordinates, exposure, source hash and orientation, and mark any lack of usable shadows. The new Sony files cover ISO 6400, 12800 and 10000 respectively. The two Olympus files cover ISO 3200 and 10000. The fixed centres above are witnesses, not a substitute for that coverage. Reserve complete new scenes, with fresh coordinates unseen in development, for a final blind pass. A model-training “held-out” label has a different meaning from a fresh classical test.

**Put real detail next to the noise.** Use registered public noisy/ISO 100 pairs and the intersection of their fixed valid, unclipped masks. Pen-pile supplies printed edges, the specific Vaxt green-leaf crop supplies foliage, and Blombukett supplies petals. Keep training-seen and held-out results separate. Add native-scale low-ISO approved RAW controls for coloured signs, eyelashes, repeating fabric and fine points, after verifying the actual subject. Run each candidate on the low-ISO source itself to expose erasure, then test an aligned higher-noise observation where available. A low-ISO shot of a different scene is a preservation check, not truth for the Canon. Real stars, particularly coloured and undersampled stars, need an approved night-sky RAW with verified stars. If the corpus lacks stars, lashes or weave, record the gap and seek an approved file or a specifically licensed real pair before declaring those subjects safe. Simulated point-spread functions remain useful for controlled flux/width checks. Clean references serve evaluation only. [Pair licences, provenance and masks](public-pairs.md)

**Measure what draws the eye.** Start with separate scores for green/magenta islands, luminance pits/rims and broad colour mottle. Use the same exposure, display transform, zoom, valid mask and spatial support for every column.

1. On finished SDR pixels, estimate a robust local colour and brightness trend across a 16–48 px ring, staying on the same side of strong ridges. Subtract the trend, smooth at radii 1, 2, 4 and 8 px, and compare the centre to the outer ring. Green/magenta is the dominant axis on the Canon. Also record the orthogonal colour error so another cast cannot earn a win. Measure 8–32 px variation separately for mottle. Use perceptual units on delivered SDR/HDR and exclude uncertain boundaries from *flat* scoring, but display them in the detail review.
2. Divide the signed excursion by a typical fine-grain spread for that brightness from a frozen reference control, with a visible-contrast floor. For each isolated footprint keep its strongest score across scales once. Report excess above the reference tail per unit area, the worst three site scores and the actual signed colour/luma deviation there. Log sparsity and the core-to-surround ratio separately. Fine, evenly distributed grain has little coherent excess at larger scales. Report finest-band brightness RMS, its block-to-block variation and adjacent-band energy alongside the score so blurring or adding grain cannot win by changing its own denominator.
3. Calibrate against Steve *before* ranking variants. On six shuffled crops include the noisy input, today’s result, a grainier control and a known over-smoothed/colour-erasing control. Ask him to mark distracting spots and tick any lost detail at normal size, then inspect at 6×. Tune scales and weights on half, freeze them, then predict his ordering on the other half. If an even-grain crop is ranked worse solely for grain, an erased letter earns a win, or he consistently marks spots the metric misses, revise the metric and validate on fresh examples. Keep ties and disagreements visible. The old island count remains available for historical comparison.
4. Keep separate hard checks for preservation. Use real point flux, width and colour, thin-stroke contrast and continuity, eyelash edge width, cloth/foliage oriented band energy and spurious texture, plus the existing clean-reference sharpness, colour, halo and exposure tests. A visible lost star or broken letter vetoes a candidate even if the flat average improves. Confidence comes from multiple *photos*. Report each camera/scene and any reversals rather than treating thousands of adjacent pixels as independent trials.

**Separate cause from fit.** For each short-listed candidate first lock the source noise model and controls across placement/algorithm variants. Then remeasure normally to quantify the interaction. Compare each track alone against today before combining two winners. Keep an Off column, check exact bypass, and watch for new islands beside corrected ones. Screen at native scale and half-resolution, all fixed lifts, then run one real-app review on the winning settings. A visually pleasing Canon-only result merits another experiment.

**Review page.** One small local page, one row per frozen site, with **Noisy | Today | Candidate**. Noisy uses the same RAW development and Denoise off, and the caption states which sensor cleanup is enabled. Each column shows the same 288 px native crop, then the same 48 px square enlarged to 288 px with nearest-neighbour sampling (6×). Put the exposure, file, sensor coordinates and a small reference outline on the row. Start at normal viewing size. In blind mode keep Noisy fixed and shuffle the other two, reveal labels after Steve marks “distracting spot”, “detail lost” or “tie”. Include real green subjects as well as neutral shadows and show a clean reference when available. Keep the fixed review folder below 20 MB with cropped PNGs only.

**Only advance a winner to app qualification.** On the Neo measure click to first clean picture, first live slider response, and export request to completed file on the same 18/42 MP inputs, plus peak app memory and fallback. Benchmark in the normal app with a warmed and a cold preparation, alternating order, and report same-machine ranges. Prior single-thread research clocks cannot predict those waits. Use existing CPU and GPU paths and bounds, including the 4 GB default and device admission. Consider an additional GPU route only with a credible roughly 50% whole-wait saving or unacceptable CPU performance. Slow candidates must be explicit choices, never initial development work. Before shipping compare Library GPU RAW with CPU, live WebGPU with CPU, and Proof with delivery/CPU fallback on matched finished pixels. Apply existing mean <1 / p99 <3 perceptual checks where specified, SDR ΔE2000 and HDR ΔE ITP, exact bypass and alpha, shifted tile seams, signed and above-white exposure from −6 to +6 stops, and the exact pre-encode target. Only the existing 1% encoder-rounding allowance applies after encoding. Verify original clips, stars beside clipped lights and Opposed/Edge boundaries. ## First decision for Steve

**Should we spend the first trial on out-of-place green and magenta, accepting that some dark pits will still be visible?** I recommend yes. Keeping brightness fixed gives lettering and eyelashes their best chance of staying sharp. A small genuine coloured light could still lose its hue, so include a coloured light or printed mark beside the Canon shadow in the first blind review. If that trial clears both tests, the next decision is whether the remaining pits warrant the risk of changing brightness in track 2. That decision can wait for the pictures.

## Reproduce the diagnosis

Start from the repository setup and the verified test-photo manifest. From `codebase` on the Mac run the command below. On Windows use the venv’s `Scripts/python.exe` and set the same thread variables in the shell. The script reads only approved originals, fits the sensor model from the photo, and writes numeric receipts. The tracked receipt includes photo hashes, per-window models, 15 constant gains, matched-site results, original marked zooms and run limits. In site records, x/y are relative to the 288 px core and the display channels are numbered R=0, G=1, B=2. The isolation score uses a 5×5 median residual divided by the median absolute residual of that channel at radius 6–12 px, floored at 0.01 display units. A reversal is counted as a loss of the original signed contrast and may still be a visible opposite-colour spot.

```sh
HDR_CPU_THREADS=1 OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
.venv/bin/python tools/gpu-run-lock.py --label denoise-speck-attribution -- \
  .venv/bin/python -m tools.denoise_eval.candidates.guard \
  --receipt output/denoise-v1/survivors/guard.json --seconds 1100 -- \
  .venv/bin/python -m tools.denoise_eval.keep_survivors \
  --output output/denoise-v1/survivors/results.json
```

Setup verified the photo corpus and reused the validated native helpers. Both fast suites passed, with 1,108 Node and 4,256 Python passes, one Node skip, 155 Python skips and one unexpected Python pass. The executable check for this research is the CPU reconstruction comparison above. No GPU driver directly exercises the research-only intervention. The final output inventory was 13.2 GB, all in the shared test-photo folder.
