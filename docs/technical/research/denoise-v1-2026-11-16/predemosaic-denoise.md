# Denoise before demosaic — November 20, 2026

**Result: the early GPU pass is fast enough to keep investigating, but none of the tested methods is ready to replace today's Denoise.** The best trial cleaned brightness and colour separately on the Bayer mosaic. At the same overall brightness noise as Clean Grain, it made the Canon shadow grain about **8 → 4.4 pixels** and the Sony portrait's **15 → 3.1 pixels**. The remaining colour mottling was worse in both shadows, Sony hair lost real structure, and 26 of Steve's 63 marked spots got materially worse on at least one measure. All three checked light cores survived unchanged. No grain was generated or added back.

## Where the RAW data is available

- **Grade / CPU development.** `loader.py` calls `raw_import.decode_raw`. LibRaw unpacks the visible, unrotated 16-bit mosaic (`raw.raw_image_visible`) and provides the 2×2 phase pattern. `_execute_raw_decode` runs optional `raw_pixel_cleanup.apply_raw` (hot pixels, then Even out harsh specks), then RAW highlight reconstruction. `_develop_libraw_camera_rgb` calls the signed native AHD in `signed_raw.py` for supported Bayer, subtracting phase black levels without clamping negative samples, then orients the result. RGB normalization, as-shot white balance, camera-to-ACEScg and lens correction are later. Non-Bayer/unsupported import uses other CPU/LibRaw routes. Mandatory mosaiced DNG opcodes have a distinct signed branch; linear DNG has no Bayer mosaic. This experiment covers ordinary Bayer only. [Import](../../../../codebase/backend/hdr_finisher/raw_import.py) · [Signed AHD](../../../../codebase/backend/hdr_finisher/signed_raw.py)
- **Library / CPU.** Recipe-aware `library_cpu_bands.develop` applies the same RAW cleanup and highlight reconstruction before storing one sensor plane and developing 256-row signed AHD bands with eight guard rows. The reduced analysis helper `library_raw_decode.decode` can request half-size signed Bayer development or LibRaw LINEAR when its camera path is unavailable; that helper is not the recipe-aware native route. Embedded-camera JPEGs never have a Bayer plane. [CPU bands](../../../../codebase/backend/hdr_finisher/library_cpu_bands.py) · [Reduced decoder](../../../../codebase/backend/hdr_finisher/library_raw_decode.py)
- **Library / GPU development.** `library_api` requests `library_gpu_raw.sensor`, which unpacks and copies the mosaic. Harsh specks are still tamed on the **CPU** before transport; when only hot-pixel removal is selected there is a separate GPU `NORMALIZE_CLEAN` path with the fit in the header. `library-gpu-raw.js` uploads the packed 16-bit samples, normalizes and gathers clipping evidence, applies opposed-colour repair, then runs `GREEN`, `HOMOGENEITY` and `COMBINE` for signed AHD and camera colour. The matching insertion point for this experiment is after `REPAIR` (or normalize on a frame without clipping), before `GREEN`. The Grade GPU **Denoise** path currently receives developed RGB, not the mosaic. A fast standalone shader at the Bayer stage is not yet a way to redevelop the visible Grade picture. [Sensor handoff](../../../../codebase/backend/hdr_finisher/library_gpu_raw.py) · [WebGPU development](../../../../codebase/frontend/library-gpu-raw.js)

**Inputs for the noise model.** Four raw black and white levels, phase-to-colour mapping, three green-normalized as-shot white balance gains, and camera colour matrices are available before AHD. Keep both greens distinct. The RAW import and Library preparer read model and ISO from EXIF/LibRaw; ISO is not a formal field in the GPU sensor header and is not a noise calibration. The actual Canon ISO 3200 file has black 2046–2047 and white 15094 counts; the Sony ISO 6400 has black 512 and white 15360. As-shot R/G/B gains are 2.382/1/1.452 and 2.391/1/1.715, respectively. Do not apply those gains before fitting the phase noise. Use them only to define a brightness direction or transform variance correctly for white-balanced data.

`raw_pixel_cleanup.configuration` fits `var = a·max(signal,0)+b` independently per phase from nine bounded sensor crops using detrended quiet 16×16 phase windows. Reuse this fit before the speck clamp changes its input distribution. For the prototypes we added the same quantization variance floor as the cleanup (`1/(12·span²)`). This is a provisional single-photo estimate, not a calibrated profile; the ISO 800 atrium fit returned zero read intercept in all phases. The normal developed RGB wavelet model and band sigmas are **not** valid parameters for this stage. Neither ISO nor the known contaminated Canon optical margins are substitutes for dark/flat captures. [Sensor fit](../../../../codebase/backend/hdr_finisher/raw_pixel_cleanup.py) · [Prior fit caveats](noise-model-and-raw-specks.md#why-not-substitute-optical-black-or-iso)

## GPU-suited shortlist

Costs below are work estimates per **one million native sensor pixels** (250,000 packed four-phase cells). Counts are logical reads/arithmetic, not DRAM bandwidth or measured times. Margins are **per side in native pixels**, before the separate eight-pixel AHD margin. Do not copy code from upstream implementations; the prototype tests the ideas independently.

| Method | Cost and margin | Evidence and choice |
| --- | --- | --- |
| Generalised Anscombe then shrinkage | About 1M scalar square roots and 1M inverse evaluations or table lookups, in addition to the chosen filter; no additional margin for the transform itself. | [Mäkitalo & Foi](https://pubmed.ncbi.nlm.nih.gov/22692910/) show why the inverse matters at low counts. [darktable RAW wavelets](https://github.com/darktable-org/darktable/blob/master/src/iop/rawdenoise.c) and [LibRaw's dcraw-derived tools](https://github.com/LibRaw/LibRaw/blob/master/src/postprocessing/postprocessing_utils_dcrdefs.cpp) provide the simpler square-root precedent. Do not simply clamp signed HDR Finisher shadows to take a root. Deferred in favour of direct variance weighting. |
| Packed three-scale à trous shrinkage | 4.5M packed-vector reads for separable 3-tap lows; up to 2.25M more for a separate shrink/reconstruct pass per scale. Radius 1/2/4 in packed cells, 14 px native. | The [darktable RAW denoise module](https://docs.darktable.org/usermanual/5.8/en/module-reference/processing-modules/raw-denoise/) treats phases independently; [Zhang et al.](https://research.polyu.edu.hk/en/publications/pca-based-spatially-adaptive-denoising-of-cfa-images-for-single-s/) demonstrate exploiting direct CFA correlation. Tested fixed group shrinkage, not a local PCA eigensolver. |
| CFA-aware guided bilateral | 13.5M packed-vector reads for three passes; 18M for the four-pass split-colour trial, plus a shared light guard and output blend. 14 px for 1/2/4; 30 px for 1/2/4/8. | [Tomasi & Manduchi](https://scholars.duke.edu/publication/802410). Tested a fixed signed CFA guide with normalized phase distances, then a stronger version separating brightness and colour. |
| Bounded patch matching on packed CFA | A 24-offset search with a 3×3 patch makes about 54M packed-vector distance pairs and up to 6M weighted accumulation taps; running sums or workgroup reuse can cut redundant reads. 10 px for a ±4 packed-cell search plus ±1 patch. | [Buades et al. with IPOL reference code](https://www.ipol.im/pub/art/2011/bcm_nlm/); darktable [profiled denoise](https://docs.darktable.org/usermanual/5.6/en/module-reference/processing-modules/denoise-profiled/) is a developed-image reference for this cost/quality trade-off, not a CFA implementation. Keep in reserve if guided weighting cannot separate structure from noise. |
| Green-mean and green-difference cleanup | One 3×3 gather over two greens is roughly 4.5M scalar taps, plus a per-cell mix and optional edge veto. 2 px for one pass; 6 px for radii 1+2. | [RawTherapee preprocessing](https://github.com/RawTherapee/RawTherapee/blob/dev/rtengine/rawimagesource.cc) provides a green-equilibration precedent, not a full denoiser. A bounded difference-only pass is worth isolating for alternating-green noise; untested here. Leave G1/G2 position-dependent detail alone near edges. |

[DxO's EP2174289 patent](https://patents.google.com/patent/EP2174289B1/en) is a precedent for denoising a Bayer mosaic before demosaicing, not evidence of the exact filter in current DxO products. The optional residual-grain step described there was not tested.

## Measured photo comparison

Read-only originals were hash-checked against the approved test set: `IMG_0790.CR2` (Canon ISO 3200), `_DSC7970.ARW` (Sony ISO 6400), `DSC05622.ARW` (high-ISO holdout at 10000), and `DSC01212.ARW` (ISO 800 small-light check). Every variant started with Even out harsh specks at ×2.5, hot-pixel removal off, default opposed-colour highlight repair, and lens correction off. The script intercepted the prepared virtual sensor in memory immediately before AHD; it altered the signed normalized mosaic and re-encoded to `uint16` for the same native AHD, normalization and camera transform. Zero-effect crops reproduced the existing AHD development. The light guard copies protected samples unmodified, not merely approximately. Independent even-origin windows with smaller halos gave identical rendered pixels on the sampled Canon flame, Sony lashes, and atrium light. The unmodified first cleanup pass tamed approximately 209k Canon / 338k Sony portrait samples; these are encoded sample counts, not a spot-quality score.

**Trials:** shared-phase wavelet shrinkage; three-pass guided Bayer smoothing; four-pass guided Bayer smoothing with separate brightness and colour strengths. The last one uses a camera-luminance projection on the correction vector, taking the full filter at 95% for the orthogonal colour part and fitting only the brightness strength. It attenuates the two differently in one reconstruction. An ablation applies today's Small colour cleanup after that candidate at 50%, with no later luminance filtering or grain synthesis.

**Match and measure.** Default Standard, Fine Grain and Clean Grain are included. Default Standard is much stronger on brightness than the two Grain modes, so a labelled Standard column also has only its Amount changed to match Clean Grain. Each trial fit one brightness strength per photo on two fixed 256×256 flats (one for the atrium), aiming for pooled, per-patch-normalized scene-Y residual RMS within 1% of Clean Grain. No fitting on marks, edges or extra flats. Scores follow [the grain-size study](grain-size-and-colour.md#how-the-comparison-was-made): 14 px trend removal, Hann-weighted median power wavelength, adjacent-pixel correlation, and two-axis colour residual power in the 8–32 px band. The photo measures are not clean ground truth; local RMS includes any fine structure in a flat patch, and the 1:1 PNGs are fixed lifted review views, not finished HDR outputs.

The split-colour trial matched the pooled brightness target within 0.6% on all three noisy RAWs (single holdout flat differences can be larger: Sony mid-check was +17%). The three-pass guided and wavelet trials matched the Canon, but even at full strength were **45–57% noisier** than the target on both Sony photos. At their matched Canon point they left about **8.5–9×** the dark-patch colour mottling of Clean Grain. They are not competitive stand-alone choices.

| Dark patch | Clean Grain | Standard, matched Amount | RAW separate colour |
| --- | --- | --- | --- |
| Canon fire-dancer | 7.95 px / .80 / .124 | 3.73 px / .37 / .759 | **4.40 px / .48 / .300** |
| Sony portrait | 14.83 px / .92 / .110 | 16.46 px / .91 / .815 | **3.14 px / .28 / .483** |
| Sony ISO 10000 holdout | 13.49 px / .91 / .096 | 17.03 px / .92 / .690 | **3.51 px / .33 / .490** |

Each cell is median brightness wavelength / adjacent-pixel correlation / 8–32 px colour RMS ×1,000 (lower colour RMS means less mottling). Splitting colour improved on matched Standard's colour in all three shadows. It still left **2.4×, 4.4× and 5.1×** Clean Grain's dark-patch mottling, respectively. The Canon floor is an exception: .454 vs .751 for Clean Grain, roughly **40% less**. The brightness grain is not always finer than matched Standard; on the Canon shadow it is slightly coarser than that weaker Standard setting.

**Detail.** Relative to Clean Grain's fixed texture/features, the split trial scored 1.16 on Sony lashes and 1.01 on Canon flame brightness edges, but only .25 on Sony hair texture (.30 on the ISO 10000 holdout), .51 on Canon face texture and .60 on the skirt. Above 1 can be added contrast or residue, not proof of recovering detail. The hair crops visibly lose strands. This is a quality failure, not a trade-off to enable by default.

**Marked spots and lights.** We located the peak once on default Standard, then applied the existing ring test to those positions for **all 38 Canon + 25 Sony marks**. Against Clean Grain, a material regression was >25% and >2 eight-bit display levels in either colour distance or pit depth. The split trial worsened **18 Canon and 8 Sony unique spots**; 14/8 colour and 11/0 pit regressions, with overlap. Seven Canon and 13 Sony colour marks newly crossed the fixed two-grain threshold; three Canon pits also crossed. It fails the zero-worse requirement. At the atrium blue-pole light `(3460,3000)`, bright railing-area lamp `(3432,3076)` and adjacent pole spot `(3427,2999)`, all three RAW-only outputs were **pixel-identical to specks-only** in the 9×9 review windows (mean/p95 ΔE2000 both 0). The pole light's peak held, but its 5 px excess above the surrounding ring fell 7.5% for the split trial: surrounding colour can still change. These are bounded SDR review checks, not certification for all small coloured lights or a finished HDR app path.

## MacBook Neo WebGPU trial

Measured in Electron WebGPU on the 8 GB MacBook Neo (Metal), alone under `tools/gpu-run-lock.py`. WGSL runs four guided passes, a light seed, horizontal expansion and a vertical expand/output mix: seven dispatches. A signed synthetic patch with Canon noise coefficients, dark negatives, an edge and two lights agreed with Python to **3.7×10⁻⁹ normalized units** and changed no protected channel. The GPU consumes packed phase floats and writes a separate result; it does not run LibRaw, black subtraction/packing, AHD, upload of new tiles, downstream Denoise or presentation inside the measured interval. GPU timings are wall time from command encoding to queue completion with input already resident.

| MacBook Neo workload | Warm time | Peak prototype texture allocation |
| --- | --- | --- |
| 110% Canon visible region, 2430×1017 core plus 44 px per side and even alignment | **7.4–7.7 ms**, median 7.5 ms; first dispatch 18.4 ms | 39.0 MB |
| Full Canon 18 MP, 12 padded tile dispatch groups | **46–70 ms**, median 54 ms | 36.9 MB per reused tile |
| Full Sony 42 MP, 24 padded tile dispatch groups | **83–84 ms**, median 83 ms | 36.9 MB per reused tile |

Full-frame rows are estimates from the measured sequential tile workload: 1536×1536 native cores plus a 44 px halo, each using the same resident tile and throwing away its output. Padding every edge tile costs more compute than needed; no packing, inter-tile transport, output retention or other pipelines costs less. This is headroom for the **filter**, not a 7.5 ms slider-to-picture claim or a memory-admission result. Keep tile origins even, preserve signed samples, read the same highlight evidence, compose the RAW dependency radius with AHD/warp/late-filter reach and measure the actual interaction in the app. Do not create a full-frame duplicate of the four phases just to pan or move a slider.

## Recommendation and later Denoise

Do **not** ship or replace the existing Denoise modes with any of these trials. Keep harsh-speck protection and highlight reconstruction unchanged. The most useful next experiment is a **weaker, structure-gated early colour pass** on packed Bayer, not a stronger brightness smoother. Use both greens and directional detail as edge evidence, and leave the measured hair, face and fabric regions alone when that evidence is strong. Compare it against Clean Grain at the same overall brightness noise, with all 63 marks and the three lights as hard screens before wiring any app controls.

Do not stack current full-strength Standard/Fine/Clean on the altered source unchanged. They measure an RGB noise distribution reshaped by the early filter, and risk double smoothing; retune their noise measurement, colour strength and band balance against the new source. The measured 50% late Small colour pass kept brightness unchanged but cut the dark-patch colour RMS only **1–2%** on the three noisy photos and rescued no marked spots. Keep a retuned lighter RGB pass as a possible second stage for residual broad colour, not as a rescue for this prototype. Non-RAW inputs still need a developed-image method. Leave grain add-back out of the next round.

It imports the November 20 grain-size metrics/region definitions from the adjacent study and uses the earlier GPU study's fit only if model and controls match. `gpu-fixture.py` makes the parity inputs; `gpu.jsonl` records the lock run. No tracked source code changed; no live app, HDR delivery or export benchmark was run for this prototype.
