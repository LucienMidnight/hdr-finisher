moves between them only through GitHub: commit and push (after asking
Steve) before switching; pull on the other machine and continue. Anything
a check needs that is not in Git (photos, fixtures, `AGENTS.md`, the lock
wrapper) must exist on both, and test tooling must run on both without
per-machine edits.

  test machine until now and stays the main Windows target. At each release

  smoke-tests the packaged app on Windows, macOS and Linux. Start it on
  `main` early in each release, and tag only after it passes everywhere.

  PC rows. Add "MacBook" to the conditions of every row you write in
  `docs/technical/performance-table.md`. Judge each speed fix by before and

## Step 0: set up the Mac (do first, then report to Steve)

Steve brings a folder from Google Drive, `mac-test-files-2026-11-13`.
Its `README.txt` says where each part goes.

1. **Code.** Clone `https://github.com/LucienMidnight/hdr-finisher.git` into
   a folder named `ai` inside a parent folder (for example
   `~/HDR Finisher Tool/ai`), as on the PC. Check out
   `feat/watermark-and-library-polish`.
2. **Agent instructions.** Copy `agent-setup/ai/AGENTS.md` to `ai/AGENTS.md`
   (Git ignores it on purpose), and `agent-setup/AGENTS.md` and
   `agent-setup/gpu-run-lock.py` into the parent folder. In `AGENTS.md`,
   read `.venv/Scripts/python.exe` as `.venv/bin/python` on the Mac.
3. **Tools.** Follow `docs/technical/development.md` and
   `docs/setup/macos.md`: Python 3.12 virtual environment in
   `codebase/.venv`, `npm install` for the app and `desktop`, and
   `./tools/build_native_macos.sh` for the encoders (`codebase/bin` holds
   Windows programs only).
4. **Test photos.**
   - `codebase/output/test-photos/...` and `codebase/local-test-media/...`
     from the Drive folder go to the same paths in the repository.
   - `Photos/` stands in for the PC's `D:/Photos`. Put it anywhere (for
     example `~/Photos`). Drivers and the three read-only projects in
     `codebase/tests/release/drivers.json` (`protectedProjects`) use
     `D:/Photos/...` paths. Add one setting that maps that root to the Mac
     folder, in the drivers and the release runner, rather than editing
     paths one by one.
   - The read-only projects (`DSC00264-four-masks`, `DSC00264-fifty-locals`,
     `DSC00950.hdrfinisher`) must never be saved over: make them read-only
     on the Mac (`chmod a-w`). They store `D:\Photos\...` source paths
     inside; if the app asks to find a moved source, do that on a copy.
   - The originals stay on the PC. One copy of each photo on the Mac.
5. **GPU lock and window size.** `gpu-run-lock.py` uses only the Python
   standard library and works on macOS, but it sets a 2560×1440 window,
   which a MacBook screen may not give. Find the largest window size the
   Mac gives (built-in screen or an external monitor if Steve uses one),
   use it for every GPU check, and record it in `AGENTS.md` and the
   performance table conditions.
6. **First runs.** Fast checks, then `node tools/quick-library-check.cjs`
   (its default folder `library-mixed-v1-run` is in the Drive folder), then
   one GPU driver (`film-stock-parity.js`). Sort failures into two lists:
   - **Platform only:** Windows paths, `.exe` names, PowerShell,
     DirectML, window size. Fix the ones that block Phase 1 checks; list
     the rest.
   - **Real failures:** name each in one line, as `AGENTS.md` says.
7. **Mac skips found in the research (A5).** Check whether the tier-overlap
   test skipped on every Mac (`codebase/tests/test_library_source_baseline.py:13`)
   now runs, and run the packaged smoke test at the Mac's real sizes once.
8. **Disk.** `tools/output_size.py` and the 100 GB limit apply on the Mac.
   If the Mac's disk is small enough that 100 GB is a problem, tell Steve
   and propose a lower limit.
9. **Report to Steve** in plain language: what works, what does not, the
   window size used, and anything that blocks Phase 1. Then start Phase 1.
