# N5: Start HDR from SDR — research only, not exposed

November 16, 2026. MacBook Neo / A18 Pro / 8 GB. Base: N4 `bd68ece2`.
Acceptance recorded in `2a136941` before measurement. **X2 is not shipped.**
No UI, public mutation endpoint or application caller imports the prototype.
Existing forward Match retains its default wheel-translation direction.
M1/M1d remain open; this work does not claim equal Film inputs or repair them.

## Method and limits

The research module captures finished SDR, preserves its input state, copies
known SDR creative settings into ordinary HDR controls and fits ten visible
controls through the real HDR renderer, five coordinate passes / 101 renders.
The reverse wheel solver transforms tint vectors directly into ACEScg and
does not invert forward highlight attenuation. Curves/HSL/Film are copied,
not fitted, and Film renders normally once. Local grades/masks are copied;
their preservation is unit-tested, not photograph-qualified in this study.

SDR and HDR are compared in physical nits / 203 in linear sRGB; HDR uses the
shared selected project reference white. No HDR gamut clamp masks colour
error. Target-derived body support (luma .005–.9, maximum channel <.98) and
colour families are fixed before fitting. Overall and every family with >=16
samples must satisfy median/P95 luma .010/.030 and OKLab .015/.040. Smaller
families are reported as insufficient coverage, never individual passes.
The synthetic population covers all seven families. No thresholds changed.

Five canonical RAWs were decoded with `library_edge=512`, then downsampled
to <=256px. Dense synthetic ramps use seven fixed-colour rays, -10..+8 stops
in 1/64-stop increments around .0324 scene-linear. Analysis excludes grain.
SDR creative fixture: Exposure -.15, Shadows 10, Midtones 8, Saturation .08,
Midtone wheel 220°/4%; Film off and Portra 400 50%. HDR starts HC-bypassed;
the seed enables Fixed cap, Start 800 / Target 1000 nits. Enabled-mode
preservation, both reference whites, authored-target refusal and input
immutability have separate unit coverage. Fit-only elapsed times exclude
decode, application startup, native processing and UI presentation. Other
CPU validation was running; these descriptive times are not a latency baseline.
The seed decodes SDR's encoded Contrast Pivot before conversion into HDR's
scene-linear physical units (`0314c900`); the table is from that final seed.

## Transition, ordering and ceiling

Dense-ray tests require finite output, no luma reversal beyond 1e-6, and
adjacent output steps <=.1 EV in the body/highlight range (luma >=.005).
Deep-black endpoint clipping is outside that body/highlight EV diagnostic.
Eleven ramp probes pass. IMG_7723 Film-off has two conservative ordering
failures on the cyan ray at luma 3.50446: -1.430511e-6 and -1.192093e-6.
Its body gate passes, but this is still not a qualified recipe. The limit
is not widened to make those small excursions disappear.

All twelve finished CPU candidate proxies have brightest BT.2020 channel
<=1000 nits (maximum observed 571.630). Additional 600-nit retained-mode
probes find 600 exactly for Peak Fit/Fixed cap and 600.000061 for Soft Ceiling/
Clip. The research detector treats the latter as **failures**, with no
pre-encoding allowance. These incumbent float-rounding results are recorded,
not repaired by changing the production renderer or the HDR ceiling rule.

The real Electron delivery check installs the two failed synthetic candidates
only inside a disposable test session, using the existing document command.
Both use the small HDR headroom fixture, not the five RAWs. At 128px with
standard sharpening, both CPU and GPU Ultra HDR deliveries and full-size
Proof pass the existing decoded-ceiling check at 1000 nits. Proof/export bytes
are identical within each renderer. Decoded brightest-channel peaks:
Film off GPU 304.019 / CPU 303.824; Portra GPU 342.280 / CPU 342.659 nits.
This checks delivery safety, **not CPU/GPU perceptual parity or fit quality**.

## Application and validation

The original HDR screen is captured with no X2 button at 1408×794 and
1100×720; both have the expected content viewport and no horizontal overflow:
`codebase/output/review/n5-start-hdr/unexposed-1408x794.png` and
`codebase/output/review/n5-start-hdr/unexposed-1100x720.png`.
No CSS, tokens or components change. `app-check.json` records the viewports,
encoded results, unchanged SDR and exact existing document-swap Undo/Redo.
That is not an X2-specific action or confirmation test.

Every Electron run uses `.venv/bin/python tools/gpu-run-lock.py`, one at a
time, with disposable profiles. The 90-second quick Library check exits zero,
reports no errors, two GPU developments and five readable stored pictures;
only 9/33 eligible photos are pictured, so this is **incomplete coverage**, not
a clean all-photo Library pass. Frozen Library fixtures are not changed.
An intermediate repeat of the new app driver stopped at the harness's “Test
export destination must be new” guard, before export. The driver now allocates
a fresh delivery directory per run; the final repeated check passes. No file
overwrite was permitted to bypass that guard.

All 1,080 forward wheel results (72 hues × five strengths × three wheels)
are exactly unchanged against N4 `bd68ece2`, tested directly with the old pure
translator loaded from Git. The same production renderer/recipe paths remain.

Final validation:

- Node fast suite: 1,071 passed, 1 skipped, zero failures (12.69 s).
- Python fast suite: 3,577 passed, 144 skipped, 1 xpassed (240.48 s), with
  one existing Starlette deprecation warning.
- Focused Python state/materialisation/wheel/reverse-research checks: 62 passed.
- New Electron research driver: pass; four decoded deliveries and matching
  Proofs, both layouts, unchanged SDR and existing document-swap Undo/Redo.
- Quick Library: incomplete 9/33 picture coverage as described above.

Unrelated concurrent tone-preview changes were present during the final fast
suites. They are not part of N5 and are left untouched. Output is 13.0 GB at
both start and end, below the 100-GB limit. Prototype commits are `919db5cd`,
pivot correction `0314c900` and repeatable export destinations `e027a097`.

## Not built / not qualified

No user action, source-eligibility rule, overwrite confirmation, runtime
revision guard, X2-specific Undo transaction, failure notification, or tooltip
is wired. Planned copy is in `sdr-match.md`, explicitly labelled unimplemented.
Independent denoise, repairs, captured-match grain, every HC mode on the five
RAWs, native/full-resolution masks and detail, HDR reference 100 on photos,
other stocks, AVIF/JPEG XL/HEIF/native-size encoded outputs and CPU/GPU fit
parity are not qualified. No broad release sweep, installer, push or protected
project writes were performed. Since body acceptance fails decisively, native
qualification and extra slow export drivers are deferred rather than used to
suggest that X2 is ready.
